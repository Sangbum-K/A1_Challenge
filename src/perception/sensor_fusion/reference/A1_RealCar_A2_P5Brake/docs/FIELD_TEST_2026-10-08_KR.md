# 2026-10-08 트랙 시험: 정지 자차 + 움직이는 앞차

자차(카메라 차)는 정지, 앞차만 움직인다. 화면에서 앞차 **거리**, 자차 50 km/h 기준
**종방향 상대속도**, **브레이크(m/s²)**, **차량 위치 트래킹**을 본다.
브레이크 값은 계산·기록만 하고 차량으로 보내지 않는다.

## 명령은 세 개

```bash
cd /home/ailab/git/sangbum/A1_Challenge-main/A1_RealCar_A2_P5Brake

./run.sh check            # 출발 전 한 번. FAIL이 있으면 고친다
./run.sh live d20         # 시험마다 이름만 바꿔서 실행, q 또는 Esc로 종료
./run.sh stop             # 이상하게 끝났을 때만
```

`live`가 알아서 하는 것: 카메라 시작, 노출 **3000 µs 고정**, 자차 **50 km/h 기준** 브레이크 계산,
원본 bag 녹화, **화면 녹화(`a2_overlay.mp4`)**, 화면 3프레임마다 갱신, 결과 폴더 `outputs/<날짜_시각>_<이름>/` 생성,
종료 후 브레이크·트래킹 그래프 자동 생성.

## 시험 순서 (이름 예시)

| 순서 | 상황 | 명령 |
|---|---|---|
| 1 | 앞차 없음 (빈 차로) 20 s | `./run.sh live empty` |
| 2 | 앞차 정지 10 m | `./run.sh live d10` |
| 3 | 앞차 정지 20 m | `./run.sh live d20` |
| 4 | 앞차 정지 30 m | `./run.sh live d30` |
| 5 | 앞차 정지 40 m | `./run.sh live d40` |
| 6 | 40 → 10 m 천천히 접근 (예: 10 km/h) | `./run.sh live approach10` |
| 7 | 10 → 40 m 이탈 | `./run.sh live recede10` |
| 8 | 옆 차로로 이동 / 옆 차로 정지 20 m | `./run.sh live sidelane` |

- 각 run은 시작 후 약 1초간 `HISTORY WARMUP`(21-frame 채우는 중)이다.
- 정지 run은 20초쯤 보고 `q`로 끝낸다.
- 거리 GT는 콘·줄자로 표시하고, 앞차 **어느 점까지**(뒤범퍼 ↔ 카메라 렌즈) 잰 거리인지 적는다.
- 속도 GT는 앞차 계기판 속도와 콘 통과 시각을 적는다.
- **안전**: 앞차는 카메라 차량에서 10 m 이상 떨어져 멈춘다.

## 화면 보는 법 (1920×910)

**왼쪽 (카메라)**: 초록 박스가 모델이 보는 영역이다. 빨간 세로 띠는 A₂ 앞차 확률,
`d=…m vL=…m/s`는 A₂가 읽은 거리·종방향 상대속도다. 박스 위 삼각형이 트래킹된 차량이고,
**자홍색이 브레이크 대상 앞차**, 하늘색은 그 밖의 차량이다.

**오른쪽 (브레이크)**:

| 표시 | 의미 |
|---|---|
| `DISTANCE` | 앞차 거리 (A₂ ch6 × 40) |
| `LONG REL @50` | 자차가 50 km/h일 때 앞차 종방향 상대속도. 음수 = 가까워짐 |
| `BRAKE` | 줄 브레이크 m/s² (−3 ~ +1). −0.5 이하이면 빨간색 |
| `gate` · 노란 막대 | 앞차를 얼마나 믿는지 (0 ~ 1). 낮으면 브레이크도 0에 가까움 |
| `track T… vL` | 트래킹된 앞차의 거리와 종방향 상대속도 (카메라 기준). **브레이크는 이 속도를 쓴다** (`vL src track`) |
| `A2 FEATURES` | 앞차 bin의 object, 종방향 상대속도, proximity, 거리 (raw / 단위 변환) |
| `TRACKING` 지도 | 위에서 본 그림. 아래 초록 삼각형이 카메라, 위가 앞쪽. 원 = 트래킹 차량, 꼬리 = 최근 5초 경로, 회색 점 = 이번 프레임 A₂ 검출, 노란 선 = 브레이크 대상 차로(bin 16–25) |
| 아래 그래프 | 최근 10초 거리(주황 = A₂, 자홍 = 트래킹)와 브레이크 |

기대 반응: 앞차가 다가오면 거리 감소 → 브레이크가 더 음수. 빈 차로·옆 차로에서는 gate ≈ 0 → 브레이크 ≈ 0.

참고 기대값 (앞차 정지, gate = 1, 자차 50 km/h):

| 거리 | ≤ 20 m | 30 m | 40 m | 50 m | 55 m | ≥ 60 m |
|---|---:|---:|---:|---:|---:|---:|
| P5 요구 | −13.9 | −13.3 | −8.3 | −3.3 | −0.8 | 0 |
| BRAKE (−3에서 자름) | −3 | −3 | −3 | −3 | −0.8 | 0 |

50 km/h 기준이면 약 52 m 안쪽에서 BRAKE가 −3에 붙는다. 거리에 따른 변화는 작은 글씨 `P5`에서 본다.

## 알아둘 것

- 9/27 같은 장소에서 A₂는 20 m 정지차를 약 29–31 m로 읽었고, 검출 위치도 좌우로 몇 m씩 튀었다.
  트래킹 지도에 차가 흔들려 보이면 A₂ 입력 문제다. 트래킹은 이를 부드럽게 할 뿐 고치지 못한다.
- 트래킹 위치는 학습 카메라 기하(수평 90°)를 가정한 값이다. 실제 카메라는 보정 전이라 m 단위는 참고용이다.
- 브레이크의 앞차 속도는 트래킹 속도를 쓴다. A₂ ch3(종방향 상대속도)는 정지차를 +10~+15 m/s로 읽어서
  화면·로그에만 남긴다. 접근·이탈 run에서 ch3, ḋ, 트래킹 속도를 실제 속도와 비교하는 것이 내일의 핵심 확인 항목이다.
- PC가 RT 커널(`6.8.1-1059-realtime`)이면 처리량이 21 FPS 경계에 있다. 합성 영상 30 s run에서
  모델 compute p95가 46.5–48.6 ms(예산 47.6 ms)로 run마다 오갔다. 화면이 끊기면 `--display-every 5`를
  붙이거나, 차량 제어가 필요 없으면 generic 커널로 부팅한다.
- 날씨 때문에 3000 µs가 너무 밝거나 어두우면(화면 상단 `OVEREXPOSED`/`UNDEREXPOSED`) 모든 run에
  같은 값으로 `--exposure 1500`처럼 바꾸고 기록지에 적는다.

## 카메라 포트 (2026-10-08 변경)

카메라는 이제 온보드 포트 `enp0s31f6`에 꽂는다. 프로필 `camlink-onboard`가 자동으로 올라오고,
`./run.sh check`의 5·6번이 OK면 된다. 포트를 또 바꿨는데 check가 FAIL이면:

```bash
nmcli con up camlink-onboard            # enp0s31f6일 때
ip -br link                             # LOWER_UP인 포트 확인
```

라이다(enp4s0, 192.168.1.201)와 같은 192.168.1.x 대역이라 카메라 주소(192.168.1.51)만 enp0s31f6로 가는
경로를 따로 두었다. `camlink`(enp5s0)를 올리면 이 구성과 충돌하니 쓰지 않는다.

실외 주간에는 3000 µs가 과노출(모델 band 46 % 포화)이었다. 화면 상단에 `OVEREXPOSED`가 뜨면
모든 run에 같은 값으로 `--exposure 1000`처럼 낮춰서 실행한다(9/27 실외 600–1300 µs).
