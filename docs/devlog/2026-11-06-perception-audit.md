## 요약

사용자가 넣어 둔 주행 영상을 보고 현재 문제와 전체 구조를 점검했다.
**가장 큰 문제는 트래커가 아니라 입력이라는 결론이 나왔다.** 카메라가 과노출이고, 초점거리 값이 실제와 크게 다른 것으로 보이며, 안전 플래그 때문에 P5 데이터가 쌓이지 않았다.
17개 문제를 찾았고, 현재 상태는 아래 표에 있다.

## 영상 분석

`perception.mp4`는 240초, 7,200프레임이다. 10 Hz로 샘플링한 2,370프레임을 프레임별로 측정했다.

| 항목 | 결과 |
|---|---|
| 모델 입력 band(y=235~485)의 백색 포화 | 평균 36.9%, 노면은 거의 흰색 |
| `no_camera_presence` | 49.7% |
| `no_confirmed_cluster` (카메라는 찾았으나 LiDAR 매칭 실패) | 39.4% |
| 카메라+LiDAR 매칭 성공 | 5.4% |
| 차가 보이는 프레임(약 65%) 중 카메라 영역 표시 / 매칭 | 41% / 7.5% |
| A₂ 존재 확률 최대값 | 중앙값 0.32 (진입 기준 0.4 미만) |
| 화면 갱신 | 약 6.7 Hz, 0.3초 이상 끊김 33회 |
| 자차 속도, P5 | 확인한 모든 프레임에서 `--` |

**해석할 때 주의할 점:**

- 영상은 당시 코드보다 이전 빌드로 보인다. 화면 문구가 다르다. 형상 필터와 GNSS ego의 효과는 이 영상으로 판단할 수 없다.
- 차량 검출은 어두운 덩어리를 찾는 근사치다. 비율은 대략값이다.
- 원시 bag과 CSV가 없어서 실패 원인을 프레임별로 확정할 수는 없다.
